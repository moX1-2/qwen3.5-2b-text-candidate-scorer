# Qwen3.5-2B Text Candidate Scorer 数据、训练与评测全流程

本记录依据 2026-09-25 的代码、checkpoint 状态、训练日志与固定测试集评测产物整理。旧的 `jev/训练笔记.md` 记录早期本机试验，所述超参数与最终集群运行存在差异；复现以本文件和 `jev/train_cluster.py` 为准。

## 1. 任务与模型

每条样本包含 `description`、长度为 2 至 5 的 `candidates`、唯一正确项索引 `gold_index`，以及语言、来源、领域等元数据。`jev/common.py:branch_prompts` 为每个候选构造一个提示，其中同时提供问题、完整候选列表和当前待判断项。文本骨干返回最后一个有效 token 的隐藏状态，含偏置的线性评分头输出一个实数。对同一题的全部候选分数执行 Softmax，再计算交叉熵。

训练脚本加载 Qwen3.5-2B 的纯文本骨干，保存 LoRA adapter 与评分头。纯文本骨干由 `jev/convert_text_model.py` 从 Qwen/Qwen3.5-2B 的原始多模态权重中提取，去除了视觉和 MTP 张量。本次转换得到 320 个文本张量、1,881,825,088 个参数、3,763,691,928 字节权重。上游提交及哈希见 `models/Qwen3.5-2B-Text/conversion.json` 的本地记录，公开包在 `docs/发布说明.md` 中保留必要校验值。

## 2. 环境与模型准备

本次集群训练使用 Python 环境中的 PyTorch 2.10.0、Transformers 5.17.0、PEFT 0.21.0。完整依赖见 `jev/requirements.txt`。`jev/setup_env.sh` 可以创建虚拟环境；可选 CUDA 内核缺失时，Transformers 会使用较慢的参考实现。

```bash
cd jev
bash setup_env.sh
cd ..
```

从 [Qwen/Qwen3.5-2B](https://huggingface.co/Qwen/Qwen3.5-2B) 取得上游权重并放在 `models/Qwen3.5-2B/` 后运行：

```bash
jev/.venv/bin/python jev/convert_text_model.py \
  --source models/Qwen3.5-2B \
  --destination models/Qwen3.5-2B-Text
```

公开仓库与 checkpoint 压缩包均不包含 `models/Qwen3.5-2B-Text/model.safetensors`。转换脚本会验证张量数量、数据偏移及输出完整性。若上游版本发生变化，应对照本次的提交与 SHA-256 再解释结果差异。

## 3. 数据准备

八个来源为 BoolQ、AI2 ARC、CommonsenseQA、MMLU、OCNLI、C3、C-Eval、CMMLU。原始文件目录布局见 `datasets/prepare_balanced_20k.py` 与 `datasets/prepare_80k.py` 的 `RAW` 路径。原始数据需从来源方自行取得，公开仓库只保留转换和抽样代码。

```bash
python3 datasets/audit_downloads.py
python3 datasets/prepare_balanced_20k.py
python3 datasets/prepare_80k.py
```

`prepare_balanced_20k.py` 生成 20,000 题训练集，每来源 2,500 题，中英文各 10,000 题；原有验证集为 1,000 题，每来源 125 题。`prepare_80k.py` 保留全部 20,000 道已选训练题，再从原始来源补充至 80,000 题，其中中文 50,000、英文 30,000。八来源的 80,000 题分布为：OCNLI 18,000、C3 11,000、C-Eval 10,500、CMMLU 10,500、MMLU 11,000、CommonsenseQA 8,000、BoolQ 8,000、ARC 3,000。

两个准备脚本使用固定随机种子。8 万题脚本按来源、题面和候选文本的指纹排除原有 1,000 题验证集，并校验输出 ID 唯一。输入格式见 `datasets/selected/schema.json`。训练使用了 MMLU、C-Eval 和 CMMLU 中来源名为 `test` 的数据，相关官方测试分片不能继续当作独立最终测试集。

## 4. 第一阶段：2 万题训练

实际运行的训练代码为 `jev/train_cluster.py`，与早期本机 `jev/train.py` 有区别。下列命令列出对 checkpoint 解释有影响的设置。单步累计 16 题，每轮为 1,250 步；实际完成两轮，共 2,500 步。

```bash
jev/.venv/bin/python jev/train_cluster.py \
  --model models/Qwen3.5-2B-Text \
  --train-data datasets/selected/train.jsonl \
  --validation-data datasets/selected/validation.jsonl \
  --output-dir runs/20k \
  --method lora --epochs 2 --gradient-accumulation 16 \
  --micro-batch-size 4 --max-length 1024 \
  --learning-rate 1e-4 --weight-decay 0.01 --warmup-ratio 0.05 \
  --eval-every 100 --save-every 50 --resume none
```

代码以 AdamW 更新 LoRA 与评分头，学习率共用 `1e-4`，前 5% 总步数线性预热，之后余弦退火。LoRA 配置为 `r=8`、`alpha=16`、`dropout=0.05`。每轮以 `seed + epoch` 洗牌。原始运行经过数次重启，因此仓库保存的曲线从最终日志解析，并按步数去重。公开 checkpoint 为第 1,250 步和第 2,500 步。

## 5. 第二阶段：8 万题热启与暂停

第二阶段从第一阶段第 2,500 步继承 LoRA 与评分头权重，重新创建优化器和调度器。每轮有 5,000 步，原计划两轮共 10,000 步。实际主运行在第 5,000 步完成首轮，训练到第 6,500 步后暂停。

```bash
jev/.venv/bin/python jev/train_cluster.py \
  --model models/Qwen3.5-2B-Text \
  --train-data datasets/selected/train_80k.jsonl \
  --validation-data datasets/selected/validation.jsonl \
  --output-dir runs/80k \
  --method lora --epochs 2 --gradient-accumulation 16 \
  --micro-batch-size 4 --max-length 1024 \
  --learning-rate 1e-4 --weight-decay 0.01 --warmup-ratio 0.05 \
  --eval-every 500 --save-every 50 --log-every 50 \
  --resume runs/20k/checkpoints/epoch-01-step-002500 \
  --reset-optimizer
```

`--reset-optimizer` 只在外部 checkpoint 热启时生效。同一输出目录中的内部恢复会读取 checkpoint 内优化器、调度器和随机数状态，并继续其步数与数据位置。`state.json` 的 `next_epoch`、`next_position` 和 `global_step` 可核对恢复点。本次提供的第 5,000 步状态为首轮已读 80,000 题；第 6,500 步为第二轮已读 24,000 题。

## 6. 训练监测与停止依据

训练日志解析脚本 `result/analysis/plot_training.py` 生成训练损失、训练准确率、验证准确率与 NLL 曲线。8 万题阶段的原有 1,000 题验证集在第 5,000 步准确率为 79.7%、NLL 为 0.5373；第 6,500 步分别为 78.9%、0.6458。2 万题阶段同样在第二轮出现 NLL 上升。第二阶段后续未继续训练。

新抽取的 200 道同来源留出题在第 5,000 和第 6,500 步均答对 169 题，NLL 分别为 0.4418、0.5313。两个阶段都使用固定的验证题和独立留出题做聚合检查；200 题的正确率精度有限。实际评测和逐题对照见 `result/evaluation-2026-09-25/REPORT.md`。

## 7. 四个 checkpoint 的推理评测

四个压缩包分别包含 `adapter/`、`score_head.pt`、`optimizer.pt`、`state.json`。下载后解压至 `result/unpacked/`，保持目录名与 `result/evaluation-2026-09-25/evaluate_checkpoints.py` 中的 `CHECKPOINTS` 一致。推理只加载 adapter 与评分头，优化器文件用于恢复训练。

```bash
python3 result/evaluation-2026-09-25/make_test_sets.py
jev/.venv/bin/python result/evaluation-2026-09-25/evaluate_checkpoints.py \
  --output-dir result/evaluation-2026-09-25/run
python3 result/evaluation-2026-09-25/summarize_results.py
```

`make_test_sets.py` 需要上述五来源的原始验证分片，以及生成后的训练集与原有验证集，用于排重。固定种子为 `20260925`；输出哈希见 `result/evaluation-2026-09-25/test_set_manifest.json`。本次评测使用 RTX 4060 Laptop GPU、BF16、最大 1024 token、每批 2 个候选分支。`evaluate_checkpoints.py` 按题保存分数、概率与正确性。公开包只提供自拟的 20 题和聚合结果；基准题与逐题预测需在本地重新生成。

## 8. 已知限制

- 候选分支分别前向计算，长题和候选数较多时计算成本随候选数增加。
- 训练 tokenizer 报告正则表达式警告，评测沿用训练时同一 tokenizer 加载方式。切换 tokenizer 配置后需重新评测，不宜混用指标。
- `best_nll` 当前没有在训练评测后更新，自动保存逻辑没有执行最佳 NLL checkpoint 选择。
- 200 道新留出题来自已有训练来源，检验同来源新样本。跨数据源、真实业务分布、拒答和多正确项尚未评测。
- 自拟题为 20 道简单单选题，适合演示候选打分，不支持总体能力估计。

## 9. RTX 4060 本机可行性记录

本机设备为 RTX 4060 Laptop GPU，显存约 8 GiB。`runs/test-run/train.log` 与 `runs/test-run/metrics.jsonl` 记录了一次使用最终集群脚本的短程成功更新：32 道训练题、16 道验证题、梯度检查点开启、每次前向 2 题、每步累计 16 题。成功记录的第 1 步耗时 23.873 秒，显存占用 4.66 GiB。该运行只证明这组设置下的单步参数更新可以完成，没有覆盖 2 至 5 候选、不同长度样本的完整分布。

按每步 23.873 秒保持不变机械计算，2 万题一轮 1,250 步约 8.3 小时；8 万题一轮 5,000 步约 33.2 小时，两轮约 66.3 小时。周期性验证、checkpoint 写入、长样本、内核回退与持续运行的温度和功率波动均未纳入。这些数值只用于说明单卡训练的时间量级，不能替代整轮实测。历史本机试验还出现过 OOM 与共享显存分页，说明短测不能直接外推长程稳定性。

推理已有完整实测。四个 checkpoint 均在同一张 4060 上加载并完成 200 道留出题，单模型用时 35.62 至 36.93 秒，约每秒 5.4 至 5.6 题；运行配置为 BF16、最大 1024 token、每批 2 个候选分支。公开的聚合记录为 `result/analysis/4060_feasibility.json`，来源为本地 `run/metrics.json`、`run_1250/metrics.json` 与两个运行清单。长期完整训练使用了 USTC 107 平台，4060 的整轮训练稳定性与实际总耗时仍未验证。
